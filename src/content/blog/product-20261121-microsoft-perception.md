# Microsoft Perception発売日と機能、AI攻撃対策を解説

## Microsoft Perceptionはいつ発売されるのか、価格と対応地域は

![Microsoft Perceptionの提供状況と機能構成](/blog-images/product-20261121-microsoft-perception/fig-1.svg)

*図：Microsoft Perceptionの提供状況と機能構成（出典：[1][2]）*

Microsoftは日本時間2026年11月18日未明に開幕した年次イベント「Microsoft Ignite 2026」で、「Microsoft Perception」の提供開始を発表しました[1]。発表は2026年11月17日付の同社セキュリティブログで行われ、記事の公開は2026年11月20日です[1]。提供開始も同じタイミングで、プレビュー（試用版）を終えて一般提供に移ったと報じられています[2]。一般提供されているのは4つのブルーチームエージェントと偵察用のエージェントで、連携機能や脆弱性の防御機能はプレビュー段階にとどまるという見方があります[2]。

価格については、今回の出典に具体的な金額の記載がなく、断定できません。対応地域も同様に、出典からは特定できません。続報となる公式の価格表や提供国一覧を待つ必要がありそうです。

機能面では、レッドチーム、ブルーチーム、グリーンチームの3つのチームエージェントで構成されます[1]。レッドチームは攻撃者視点で脆弱性を発見し、ブルーチームは検知・調査・インシデント対応を担い、グリーンチームは脆弱性やバグの修復とリスク低減を担当します[1]。これらは「プレイブック」と呼ばれる手順書に従って自律的に協調動作し、重要な判断では人間の判断を仰ぐ設計です[1]。グリーンチーム向けのプレイブックはMicrosoftのプラットフォームに加え、AWSやGoogle Cloudもカバーすると説明されています[1]。

新しいセキュリティ製品の価格や対象地域は、発表の華やかさの陰で後回しにされがちです。あなたの職場では、こうした基本情報を誰が最初に確認する役割でしょうか。

## 3つのエージェントチームはAIの攻撃にどう立ち向かうのか

![3つのエージェントチームの役割分担](/blog-images/product-20261121-microsoft-perception/fig-2.svg)

*図：3つのエージェントチームの役割分担（出典：[1]）*

Microsoft Perceptionは、「レッドチーム」「ブルーチーム」「グリーンチーム」という3つのチームエージェントで構成されています[1]。それぞれの役割は次のとおりです。

- レッドチームエージェントは、攻撃が行われる前に攻撃者視点で脆弱性を発見する役割を担います[1]。
- ブルーチームエージェントは、サイバー攻撃の検知と調査、インシデント対応を担います[1]。
- グリーンチームエージェントは、脆弱性やバグの修復あるいはリスク低減を担います[1]。

この3つのチームエージェントは、「プレイブック」と呼ばれる手順書に従って日常的に協調して自律的に動作します[1]。サイバー攻撃が発生することを未然に防ぎ、あるいはサイバー攻撃に対してマシンスピードでの対応を実現します[1]。ただし、重要な判断が必要な段階では人間の判断を仰ぐようになっています[1]。グリーンチームエージェント用のプレイブックでは、Microsoftのプラットフォームだけでなく、AWS、Google Cloudもカバーしていると説明されています[1]。

AIを用いたサイバー攻撃は完全に自動化されつつあるため、発見から攻撃までの時間や攻撃そのものにかかる時間は劇的に短縮されています[1]。そのため人間による操作では対応が困難になっており、対抗する側もAIエージェントによるマシンの速度で動く必要があります[1]。3つのチームが手順書を共有しながら役割を分けて動く構成は、攻撃と防御の分業を機械の時間軸に載せ替える試みだといえそうです[1]。日々の点検を人の目だけで回すのが難しくなった現場にとって、この仕組みがどこまで頼れる相棒になり得るのか、気になるところではないでしょうか。

## 既存のセキュリティ製品と比べて、何が違い、何が同じか

![既存製品との違いと共通点の整理](/blog-images/product-20261121-microsoft-perception/fig-3.svg)

*図：既存製品との違いと共通点の整理（出典：[1][2]）*

既存のセキュリティ製品との違いを、発表内容から読み取れる範囲で整理します。

まず構成の違いです。Microsoft Perceptionは「レッドチーム」「ブルーチーム」「グリーンチーム」の3つのチームエージェントで構成されます[1]。レッドチームは攻撃者視点で脆弱性を発見し、ブルーチームは検知・調査・インシデント対応を担い、グリーンチームは脆弱性やバグの修復、リスク低減を担います[1]。これらは「プレイブック」と呼ばれる手順書に従って日常的に協調して自律的に動作します[1]。単機能のツールを人が操作する従来型とは、役割分担と連携の設計が異なると読み取れます。

人間の関与の位置づけも特徴です。重要な判断が必要な段階では人間の判断を仰ぐ仕組みになっています[1]。完全自動化ではなく、判断の要所を人に残す設計です。

対応範囲では、グリーンチーム用のプレイブックがMicrosoftのプラットフォームだけでなくAWS、Google Cloudもカバーすると説明されています[1]。マルチクラウド環境を視野に入れた点は、自社製品内で完結する製品との違いとして挙げられます。

提供状況については、4つのブルーチームエージェントとReconエージェントが一般提供され、統合機能と脆弱性シールドはプレビュー段階とされています[2]。同じ「提供開始」でも機能ごとに段階がある点には注意が必要です。

一方、共通する部分もあります。AIを用いた攻撃が完全に自動化されつつあり、人間の操作では対応が困難になっているという問題意識が前提にあります[1]。防御側もマシンの速度で動く必要があるという考え方は、AIエージェントをうたう他社のセキュリティ製品と方向性を同じくするものです[1]。

道具が賢くなっても、最後に責任を引き受けるのは人なのだと考えると、この設計の置きどころが見えてきます。

## 自社のセキュリティ運用は、導入後にどう変わるのか

*図：導入前後のセキュリティ運用の変化（出典：[1]）*

導入後、自社のセキュリティ運用はどう変わるのか。発表内容から読み取れる範囲で、期待される変化を予想として描きます。

まず変わりそうなのが、日々の点検の担い手です。Microsoft Perceptionは「レッドチーム」「ブルーチーム」「グリーンチーム」の3つのチームエージェントで構成されます[1]。レッドチームは攻撃者視点で脆弱性を発見し、ブルーチームは検知・調査・インシデント対応を担い、グリーンチームは脆弱性やバグの修復、リスク低減を担います[1]。これらは「プレイブック」と呼ばれる手順書に従って日常的に協調して自律的に動作するとされています[1]。人が都度指示を出す運用から、手順書を整えて見守る運用へと重心が移っていきそうです。

次に、対応の速さの前提が変わる可能性があります。AIを用いたサイバー攻撃は完全に自動化されつつあり、発見から攻撃までの時間や攻撃そのものにかかる時間は劇的に短縮されているとされています[1]。そのため対抗する側もAIエージェントによるマシンの速度で動く必要がある、というのが発表の立場です[1]。運用の現場では、一次対応をエージェントに任せ、人は判断に時間を使う形が現実味を帯びてきます。

ただし、人の役割が消えるわけではありません。重要な判断が必要な段階では人間の判断を仰ぐようになっています[1]。承認やエスカレーションの線引きをどう設計するかが、導入後の運用設計の中心になりそうです。また、グリーンチーム用のプレイブックはMicrosoftのプラットフォームだけでなくAWSやGoogle Cloudもカバーすると説明されています[1]。複数クラウドを併用する環境では、点検の目がこれまでより広がるかもしれません。

手順書を整える仕事は、地図を描いてから旅に出る作業にどこか似ています。

## 日本企業が今日から確かめたい、価格と実運用の限界

価格に関する記述は、今回の出典には見当たりません。Microsoftは日本時間11月18日未明の「Microsoft Ignite 2026」で「Microsoft Perception」の提供開始を発表しました[1]。提供開始の時期は公表されていますが、日本企業が導入判断に使える料金体系や見積もりの情報は、少なくとも出典1・2・3には示されていません。価格を前提にした予算組みは、続報を待つ形になりそうです。

実運用の輪郭は、出典2から一部読み取れます。4つのブルーチームエージェントとRecon Agentが一般提供（GA）となり、連携機能と脆弱性シールドはプレビュー段階とされています[2]。つまり、発表時点で「全機能が完成した状態で使える」わけではないという見方があります[2]。日本企業が今日から確かめたいのは、自社の監視対象にどこまで対応するかという点です。グリーンチームエージェント用のプレイブックはMicrosoftのプラットフォームだけでなくAWS、Google Cloudもカバーすると説明されています[1]。クラウドを併用する企業ほど、適用範囲の確認が実務の出発点になりそうです。

運用の限界も押さえておきたいところです。3つのチームエージェントは「プレイブック」と呼ばれる手順書に従って自律的に動作しますが、重要な判断が必要な段階では人間の判断を仰ぐ仕組みです[1]。完全に人手が不要になるわけではなく、手順書の整備と判断を引き受ける体制が前提になりそうです[1]。AIによる攻撃は完全に自動化されつつあり、発見から攻撃までの時間が劇的に短縮されているため、対抗側もマシンの速度で動く必要があるとされています[1]。自社のインシデント対応手順がその速度に耐えられるか、という視点が要ります。

数字の出どころについては、出典1がMicrosoftのセキュリティブログと発表を基にした報道で、出典2がSecurityWeekの記事を転載した二次情報です[1][2]。出典3は2025年3月時点の別のSecurity Copilot関連記事で、Perceptionの価格や提供条件を示すものではありません[3]。導入検討では、一次情報の発表資料に当たるのが確実でしょう。

次の一手としては、プレビュー段階の機能と一般提供の機能を分けて整理し、自社のクラウド構成と照らして適用範囲を確認する進め方が考えられます。手順書の整備は、ツール導入と並行して進めるとよさそうです。あなたの職場では、どの判断を人間が持ち続けるかを決めていますか。

## 編集長の眼

Microsoft Perceptionは、攻撃者視点で弱点を探すレッドチーム、検知と対応を担うブルーチーム、修復を進めるグリーンチームという3つの役割を、手順書に沿って自律的に協調させる仕組みです[1]。私たちの仕事の現場では、たとえば情報システム担当者が夜間のアラート対応をエージェントに一次任せし、朝には人間が判断すべき案件だけを確認する、といった運用が現実味を帯びてきます。複数のクラウドを併用する企業なら、AWSやGoogle Cloudも視野に入れた点検の目が日常的に回り始めるかもしれません[1]。重要な局面では人が判断を引き受ける設計も、現場の安心につながりそうです[1]。まだ価格や対応地域は見えず、機能ごとに提供段階が分かれるとの見方もありますが[2]、防御側がマシンの速度で動くという発想は、日々の運用の重心を少しずつ変えていくのでしょう。手順書を整え、任せる範囲を決め、人が引き受ける判断を残す——そうした準備が進むほど、この製品は頼れる相棒に近づいていきそうです。
